# FileDock 代码质量与性能 Review — 2026-10-24

基线：本地发布版本 1.14.1/build19。本轮检查源代码、异步任务与资源生命周期，并使用隔离文件和模拟后端验证，不修改用户文档或音乐播放状态。性能数字来自本机测试，不代表屏幕帧率。

## 本轮已修复

| 优先级 | 问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 书签持续累积，写入配置可能超过读取器的 16 MiB 上限，导致下次启动无法读取自产配置 | 回收无引用书签；保留工作区、当前路径、历史、自定义图标和转移中的授权；超限时保留原配置并报告错误 |

| P2 | 带 EXIF 旋转或镜像的照片导入后方向丢失 | 在原尺寸内变换像素，输出统一方向；覆盖 1–8 全部方向 |

## 前次发现（1.19 状态已更新）

1. **已在 1.19 修复；原 P2：重命名父目录没有即时迁移所有子路径引用。** 此前 `rename` 仅精确匹配被重命名路径，遗漏子文件引用与历史。现已复用 `relocateReferences` 并覆盖父子路径迁移。
2. **已在 1.19 收敛；原 P2：普通文件夹的网页图片下载没有全局并发或总内存限制。** 此前普通文件夹入口为每个网页图片地址启动独立会话。现已删除重复入口，与暂存共用有界导入队列；系统交付原始 provider 数据之前的内存仍由系统管理。
3. **已在 1.20.1 修复；原 P2：Spotlight 候选过滤阻塞主线程。** 元数据项提取和文件验证在受限后台任务中执行，使用查询暂停保护、无进展超时、取消和旧代次隔离；真实系统查询另做烟测。
4. **1.20–1.20.1 已处理主要重复派生计算；原 P3：列表和暂存路径反复计算。** 目录初始排序在工作线程准备，渲染复用排序/搜索结果，暂存路径缓存按工作区或绑定变更失效。三个主文件职责仍较多，后续可分阶段拆分，避免在一轮性能修复中大范围重写。

## 1.19 拖放、暂存、预览与升级复审

本轮逐文件审阅了变更，优先修复以下问题：

- 原生文件拖放直接读取 AppKit 会话中的完整本地 URL，不再依赖 SwiftUI 是否保留原来的 fileURL 表示。内部重排仍核对实际来源、绑定的剪贴板、changeCount 与每一项令牌；Finder 文件不需要私有令牌。原始 fileURL 优先于系统合成的旧格式，防止非本地 URL 被错误转换成路径。
- 父容器使用 transformAnchorPreference 追加区域，保留子标签和文件项锚点；真实 NSHostingView 层级测试覆盖了此前被父区域覆盖的回归。整个面板使用一个持续存在的原生文件接收视图，标签、收藏、暂存及文件区通过几何区域路由；滚动裁切后的标签区域不接收拖放。同目录及跨标签共用细线插入位置；文件夹中央作为子目录目标，两侧用于插入。异步转移后，以实际输出文件名保存目标顺序，保持拖动组顺序并处理重名。暂存插入更新引用顺序后重新请求快照，避免旧快照被上下文检查丢弃后不再刷新。悬停时显示实际复制／移动／引用动作与目标高亮。跨标签释放时锁定目标；后续切换界面不会改变文件去向。收藏仅记录引用。同目录重排继续独立处理，不改动磁盘内容。
- 原生拖拽结束以实际 NSDraggingSession 身份匹配；鼠标释放后的遗留会话有宽限期清理，旧回调不能清除新会话。剪贴板解析按原生会话缓存，不随每次鼠标更新重复解析整批文件。
- 实际文件复制、移动、父子选择去重和元数据检查移到后台，最多三个文件转移任务；同名文件不覆盖。转移期间保留书签作用域，移动和重命名会迁移子文件引用及目录顺序，源目录顺序覆盖目标处的过期记录。
- 图片、SVG、文件表示和网页图片共用导入流程。全局最多两个导入批次、每批最多 128 个 provider，网页下载最多两个。等待超时会终止批次、忽略迟到回调；已开始的磁盘写入仍占用活动票据，升级与退出需等它实际返回。文件 URL 桥接也有一次完成与超时保护，缺项不移动半个选区。
- 文件夹快照额外包含有界的 Finder 自定义元数据；Tahoe 颜色标签与符号参与缓存版本，显式自定义位图优先。图标文件系统读取改为最多两个后台读取、最多 64 个排队请求，刷新时保留旧像素。分栏父目录不再在 SwiftUI body 中同步扫描。
- 空格预览不再为整批 URL 在主线程调用 fileExists；预览索引检查防止迟到请求越界。保留之前验证过的预览层级、原生内容浏览和文档状态策略。
- Sparkle 2.10.0 依赖锁定归档摘要。更新源、发布说明及 ZIP 使用 Ed25519；必须在解压前校验，不允许签名失败到期后降级。固定主应用代码身份不变，嵌套助手逐层签名；升级重启和普通退出都等待真实文件写入。取消升级会撤销旧的延迟重启回调。

右上角收藏、暂存、添加及关闭使用统一 30×32 尺寸和 4pt 间距，包含角标。

### 开合与布局连续性复审

- 加载和转移状态改为不占布局空间的浮层，读取提示延后 150ms；展开结束后使用后台刷新，避免刚展开就插入一行再删除。最近四个小型目录快照可即时复用（每个最多 1,000 项、15 秒有效），仍进行新鲜后台读取。
- 缩略图资产键不再包含拖动/动画状态。动画、拖动和隐藏时暂停新解码，保留已显示像素；新出现的单元也先复用缓存。实际 Quick Look 请求最多四个、排队最多 128 个，取消中的请求直到真实回调才释放并发槽，迟到回调不能覆盖新文件。
- 图标完成通知按路径合并成批，避免每完成一个图标就更新所有可见项。位图转换移至已有有界后台队列；暂停期间合并通知，结束后统一恢复。
- 从刘海拖出期间固定顶部几何与原来的关闭按钮可见性；鼠标释放后以 180ms 切换布局，再恢复详细渲染。减少动态效果开启时立即完成布局。关闭按钮仅在固定时显示。
- 新安装默认设置来自用户确认的当前偏好；旧配置中缺失的历史可选字段继续使用原兼容值。只复制一般设置，不复制文件路径、工作区 UUID、书签或系统权限。登录项仅在首次正常启动时按默认值登记，测试和演示模式不会登记。

新增 RenderingContinuityTests 覆盖缓存缩略图连续性、取消与迟到回调、实际并发槽、按路径通知、拖出布局冻结和释放、快照容量/过期及菜单栏图标边界。用户已实测确认连续开合和拖出顺畅，未固定时 × 隐藏正常；这些结果不等同于逐帧 GPU 测量。

新增回归覆盖跨工作区真实复制/移动、收藏接收本地 SVG/目录/文件、父子选择、路径迁移、失效目标、拖拽取消与旧回调、provider 超时与迟到数据、一次完成、Finder 标签像素及符号版本、升级延迟/取消和实际 SDK 代理选择器。隔离应用还运行签名校验、替换与重启的真实升级测试，并核对篡改输入不会替换已安装应用。

本次 500 次命中图标缓存读取约 0.0003 秒（单次本机测量），读取不接触磁盘。原有 500 项暂存基准仍属于前次测量，不把它当成本轮新成绩。

仍需注意：Spotlight 候选过滤和派生列表重复计算已在 1.20–1.20.1 中处理；不在这一轮大规模重写模型。系统文件调用无法强行中断，超时不会凭空释放仍在运行的磁盘操作。第三方 provider 的原始数据缓冲由系统交付，解码/导入阶段的限制不能宣称约束其交付前的内存。未宣称完成 GPU 帧率、所有网络盘、全部 Finder 未来元数据格式或所有 macOS 版本的像素一致性测试。

## 1.19.2 设置窗口与刘海避让

打开设置时，嵌入面板从 statusBar 降到 floating 层，但整个窗口仍伸入系统菜单栏区域。此前只对两侧控件加顶部间距，无法保护背景上边缘和中央音乐区，还会改变文件区高度。最终实现保持嵌入面板的位置、尺寸和 statusBar 层级，提高自身辅助界面的层级。文件对话框根据实际背景和父弹窗层级置顶，不再降低浏览器。设置、颜色选择器和 Sparkle 窗口使用弱引用快照，仅恢复仍由协调器管理的层级，避免覆盖其他所有者的改动；模态期间暂停协调。颜色/更新窗口首次成为 key 时立即同步，保留已有定时校验。

WindowPresentationTests 验证主面板 frame 与菜单栏保护保持不变、设置/颜色/更新层级、重复切换和精确恢复、嵌套对话框、异常恢复、模态作用域隔离、外部层级修改保护及 Quick Look 优先级。关于页直接使用 NSApplication 的正式应用图标，删除替代图案。旧的局部顶部补偿已移除，设置开关不再引起头部或音乐区重排。

1.19.3 在辅助窗口发现入口增加显式排除列表，防止 NSApp.windows 中的菜单栏图标等浏览器基础窗口被当成更新弹窗提高层级。回归测试验证即使这些窗口混入候选集合也保持原级别。用户已实测确认 build37 的主面板位置不动、顶部完整且设置/更新/文件选择器显示正常；后续排除保护不改变这些交互。

### 1.20.2 文件选择器显示生命周期回归

后续现场反馈显示，添加时文件选择器仍会被主面板遮挡。真实原生探针复现：显示前赋予的 26 级在 `NSSavePanel.runModal()` 内被重置为普通 modalPanel 的 8 级，而主面板为 statusBar 的 25 级。此前只使用从未显示的 NSWindow 测试，无法覆盖系统面板真正进入模态循环时的重置。[Apple 的接口说明](https://developer.apple.com/documentation/appkit/nssavepanel/runmodal())确认该调用会进入 NSApplication 的模态循环。

模态作用域现在只监听当前弹窗的首次及后续显示更新、取得焦点事件，发现层级低于目标才校正，不累计增加层级、不降低更高层级；结束或抛错时先移除监听，再恢复快照。主面板不降级、不移动，也没有常驻轮询。覆盖所有现有统一选择器入口。

WindowPresentationTests 增加显示阶段重置、无焦点修复、通知对象隔离、重复通知、嵌套、异常与结束后监听移除测试。独立 `test-window-panels.sh` 使用真实 NSOpenPanel / NSSavePanel 自动打开并取消六个场景，核对窗口属性和 WindowServer 合成层级、主面板位置及级别保持、重复打开和设置导出。该测试会短暂显示窗口，故作为显式选择的原生回归脚本；常规 `test.sh` 保持无可见窗口。


## 1.20.0 大目录渐进读取与应用略览

此前整个目录的枚举、逐项元数据读取、文件存在性探测与文件夹属性读取共用一个总计 5 秒的硬期限。目录有持续进展也会被误判为超时；视图反复读取 visibleEntries 会重复排序与搜索，每次扫描还会构造全部快照字符串。

- 使用新的浅层 DirectoryEnumerator 分批读取，跳过子目录和包内容，复用本次枚举预取的资源值，直接比较 FileEntry 元数据。普通独立 FileEntry 仍丢弃旧资源缓存，保持 Finder 颜色、自定义图标刷新语义。[Apple 接口说明](https://developer.apple.com/documentation/foundation/filemanager/enumerator(at:includingpropertiesforkeys:options:errorhandler:))。
- 单个锁保护取消状态、进度时间和一个待显示快照；不按文件创建主线程任务。首批小快照及随目录规模降低的更新频率，限制复制和重绘成本。底层系统调用仍不能强制中断，最多三个真实未完成读取，取消/超时不提前释放槽位。
- 5 秒改为无进展期限，每个元数据项和后台排序检查点更新心跳；排序和首轮排序结果在工作线程准备。显示层缓存排序和搜索结果，只在数据、搜索、排序、分组、手动顺序或位置改变时失效。无变化的后台扫描不发布整个浏览器刷新。
- 首次读取/导航分批显示；已有内容的后台刷新完整后再替换，避免文件暂时消失。完成前不裁掉尚未读到的选中项。导航提交后的请求上下文同步更新，继续拒绝旧路径、旧代次回调。缓存仅收完整结果。
- 定时刷新不积累尾随扫描，耗时目录按读耗时自适应到 2–30 秒间隔；手动和文件操作后的刷新可绕过此节流。
- .app/.appex/.xpc/.bundle/.plugin/.prefPane 不进入内嵌预览和空格快速查看，原生预览宿主也再次过滤。文档包如 .pages/.key/.rtfd 保持预览；应用图标和基本信息仍可查看，显式打开操作保留。

AirDrop 使用 [NSSharingService](https://developer.apple.com/documentation/appkit/nssharingservice) 与 [sendViaAirDrop](https://developer.apple.com/documentation/appkit/nssharingservice/name/sendviaairdrop)；不访问私有无线接口。系统选择接收方前临时隐藏本应用高层级窗口，完成或取消后恢复；窗口位置、层级、固定状态不变，已关闭窗口不复活。自动唤醒暂停，用户隐藏应用或正在退出时不重新显示。

AirDrop 开关保存在配置中：默认开启、旧配置缺字段时开启，关闭后隐藏直接入口并通过公开 sharingServicesForItems 委托过滤普通共享菜单中的 AirDrop。过滤使用系统返回的本地化服务标题，不调用私有服务标识；只影响新请求，在途共享保留完整生命周期。

Apple 音乐使用本机公开 Music.sdef 中的 Apple Events，后台查询不提示授权、不启动播放器；只有明确点击连接才请求权限。网易云音乐仅调用唯一且启用的原生播放菜单，布局不匹配时显示异常而不发送全局媒体键。自动模式优先正在播放的应用，多个同时播放时保留当前目标。

测试包括原有目录、拖放、SVG 暂存、框选、排序、预览、触发与更新套件，并新增部分引用重排、配置准入、播放器选择与过期命令、AirDrop 生命周期、共享窗口恢复及自定义图标队列测试。真实 macOS 图标/共享服务需要在非隔离环境验证；隔离环境的 LaunchServices 不可用不能视为应用未安装或 AirDrop 不受支持。非隔离只读探测已确认本机 AirDrop 服务存在且接受临时文件/目录。

验证边界：不宣称所有第三方客户端版本均已验收。网易云音乐未在本机安装，官方安装包 CDN 拒绝下载，因此菜单/标题适配有自动化夹具覆盖，仍缺实际客户端验证。AirDrop 真实跨设备传输需用户自行选择接收方；测试没有发送个人文件。未测量所有网络盘、GPU 帧率或长期内存曲线。

### 1.21.2 AirDrop 图标直接拖放与菜单合并

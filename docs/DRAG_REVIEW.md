# 拖放回归审查

本次对照历史稳定实现与 1.35.0 候选版，检查文件排序、跨工作区投放、拖文件夹创建标签、普通标签与固定图标排序、暂存、颜色标签和 AirDrop。

## 对照与发现

- `89ea2de`（1.19.0 build 32）至 `6eb9499`（1.34.1）的原生文件拖放由一个统一接收器负责。标题标签、文件区与功能入口提供几何位置，接收器解析目标并执行操作。
- build 84–89 的颜色拖放修复新增了位于其他文件目标上方、同样注册文件 URL 的全窗口接收器。其局部命中判断不能代替 AppKit 的实际目标选择；它可能使文件区、跨标签与新标签创建都失去原生更新。
- 同时增加的单个色点接收器和窗口级文件注册进一步扩展了竞争路径。build 90 缩小了颜色接收器范围，但尚未得到真实鼠标验证。
- 文件拖动源、工作区私有拖动类型、域隔离和标签顺序保存相对历史实现没有对应的结构性变化。工作区拖动新增的释放后恢复是为解决结束回调丢失，不负责文件投放目标选择。
- 认证绑定前的失败缓存、过时鼠标事件判断和无坐标兜底也有风险；此前合成测试直接调用已选目标，未能证明 WindowServer 实际选择相同目标。用户对 build 89 的实测仍然失败，不能将这些局部测试当作修复完成。
- 候选版扩大本地事件监控后，对滚轮事件读取 `eventNumber` 会触发 AppKit 异常；已用不发布事件的真实滚轮对象复现并修正为事件类型、窗口编号和时间戳，键盘与滚轮对象回归通过。

## 修复原则

恢复一个置于最上层的原生文件接收器，统一处理文件区、标题插入位置、工作区、收藏、暂存、颜色和 AirDrop。普通点击、窗口移动及工作区私有拖动继续透传。删除独立颜色和窗口级文件注册，避免返回拒绝后依赖系统转发到另一目标。

保留真实来源与粘贴板认证、来源允许的移动／复制操作、SVG 和任意文件引用、图片与文件提供方兼容、颜色赋值及安全撤销。没有可靠落点时不能静默把文件排到末尾。分组内排序保留组内约束，不修改其他组或文件元数据。

## 验证边界

原生宿主回归需检查注册结构、三个文件视图、普通文件夹与引用根目录、插入线状态和落位、标签首尾／间隙新建、跨标签投放、直接拖入颜色，以及私有标签排序透传。图片／暂存提供方回归另行覆盖。

真实 Finder／FileDock 鼠标拖放、可见插入线、悬停与收回仍必须用安装后的候选版核对。诊断编译只记录事件阶段、状态和几何，不记录文件名或路径；正式构建关闭诊断。未完成实机验证前不发布候选版。

## 单一路由的定向回归

已通过原生宿主检查：整个视图树仅有一个注册文件 URL／旧式文件路径类型的原生目标；颜色条的移动、复制、撤销、缩放和隐藏；普通文件夹与引用根目录三种视图的排序；文件夹新建标签及跨标签实际 SVG 复制；工作区／固定图标私有类型的活动域隔离；窗口拖动和真实滚轮对象的安全事件身份。对应日志位于本地工作区，不包含用户文件名或路径。

这些检查覆盖视图结构与实际文件结果，不能代替 WindowServer 的真实目标选择。

## 实机与最终核验

用户在 build 91 确认：文件区插入细线与落位恢复，拖文件夹至标签间隙有创建指引，跨标签实际复制成功，Finder 直接颜色拖放和无须再次点击的撤销成功，普通标签／固定图标的首尾与间隙排序正常；未固定面板自动收回正常。匿名日志同时记录到已认证本地来源、统一目标与2pt插入反馈。

本轮全量回归除文件名悬停的一个断言首轮失败外均通过；该测试在实机拖放结束后单独复跑通过，随后窗口拖动、设置、文件夹新建标签与样式测试均重新编译执行通过。正式构建不启用诊断编译标志。刘海外观的主观调整由用户明确留待后续讨论，不计为已验收的视觉效果。

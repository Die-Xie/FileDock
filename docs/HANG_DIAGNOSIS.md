# 1.17.1 卡死现场与修复

2026-10-24 对已卡住的 1.17.0/build22 实例采样 8 秒。主线程的 6,860 次采样全部停在以下调用链，进程 CPU 接近 0：

```text
workspaceTab 悬停回调
  → HubModel.selectWorkspace
  → HubModel.refresh
  → FileManager.contentsOfDirectory
  → DirEnumRead / open / __open
```

这说明该次故障是主线程等待文件系统响应，并非音乐授权、动画计算或互斥锁自锁。采样没有确定具体目录或底层存储为什么迟迟不响应，因此不将其归因于某个特定云盘、网络盘或系统服务。

修复把交互扫描统一转入 `HubDirectoryLoader`：首次加载、工作区切换、手动刷新、目录跳转和最近使用中的 FileEntry 信息读取均走同一入口。视图计算路径名称和排序时使用路径字符串或已解析的缓存，不再额外访问文件系统。路径跳转成功后才提交历史，失败时保留原目录，重试继续针对失败的目标。

底层文件系统调用不能靠 Swift 任务取消立即打断。加载器在 5 秒后结束界面等待，但保留真实未完成任务的槽位，直到系统调用返回；最多保留 3 个读取任务。检查取消标记后停止后续元数据读取，忽略失效结果。已经超时的目录不会被定时器不断重试。错误以内联提示显示，保留切换、收起和手动重试入口。若全部工作槽位都被系统调用阻塞，新读取会明确报告繁忙，而不是继续新增线程。

回归测试分别覆盖：

- 故意阻塞读取时，主线程心跳继续执行，仍可加载其他工作区；
- 超时、取消后不提前释放槽位，限制实际并发任务数量；
- 取消/超时后系统调用返回，不会再次回调或覆盖新工作区；
- 定时器不会反复重试已经超时的目录；
- 导航失败不改写路径和历史，重试仍指向原目标；
- 最近使用查询会话结束后，旧回包不能覆盖返回后的新会话；
- 原有排序、父子路径快捷键、书签、暂存及配置保护行为。

基础模型语义测试注入即时的临时文件加载器；另有真实异步生产调度器测试和后台刷新测试，避免把同步夹具的通过当成界面响应性的证据。测试不会修改用户文档或操作音乐播放。

本修复不表示所有文件系统工作都已完成异步化。手动文件操作、系统图标解析和 Spotlight 源的候选过滤仍需分别审查；本次修复范围以上述现场调用链及统一目录读取入口为准。
